# 聚类端点证据修复方案

日期：2026-09-06。状态：已实施，最终全量验证、独立复审及同机性能验收通过；执行记录见末尾。

审阅基线为 `v0.3.1`（`5c45f1b`）及其后的当前未提交改动。三个问题均已用独立的小输入复现：overlap 的问题是新增回归，另外两个 clusterj 问题在基线版本也存在。

本文是内部设计文档。`docs/design/**` 已被 Cargo 源码包排除，不添加到 README 或二进制发布归档。

## 1. 修改目标与边界

修复以下结果错误：

1. overlap 新增的同 5′ 端合并规则导致 SL 保护在后续轮次中丢失。
2. clusterj 对完全相同结构选择最后一条 read，导致混合 SL 分数时输出依赖输入顺序。
3. clusterj 允许受支持的 3′ 端点经过低支持的中间代表，最终错误地并入远处参考。

保留当前按完整 corrected locus 计算并冻结支持度的方向。修改重点是代表选择与证据保留，而不是重新累计合并后的成员数。

本次不引入新依赖、CLI 开关、公开 Rust API 字段或输出 schema；不调整默认阈值、junction correction、下采样、gene-local unique counting 或 modification 的全局唯一赋值要求。也不借此重写两种聚类算法、取消 batching 或统一两种模式的分数边界。

## 2. 可复现的验收输入

以下用 `T(start, end, score)` 表示 `chr1` 正链上的两外显子转录本，外显子为 `[start, 200)` 和 `[500, end)`。每条 read 使用不同名称；参考与 reads 通过各自输入指定身份。

| 编号 | 输入与参数 | 当前结果 | 修复后的要求 |
| --- | --- | --- | --- |
| A：overlap SL 丢失 | 参考 `T(0,1200,100)`；reads 为 `T(100,800,20)`、`T(100,1000,0)`、`T(150,1100,0)`；其余采用 overlap 默认参数 | `batch_size=0` 保留参考和 `T(100,1000,0)`；`batch_size=2` 只剩参考 | 两种设置均保留参考和原有 SL 结构 `T(100,800,20)`；普通 reads 仍可并入参考 |
| B：clusterj 输入顺序 | 参考 `T(0,1000,100)`；三条同结构 reads 为 `T(100,1000,12)`、`T(100,1000,12)`、`T(100,1000,0)`；`sw_score=11` | 普通 read 排最后时仅剩参考；反转顺序后保留参考和替代 isoform | 所有排列均保留同一个替代结构，规范排序后的 BED 和 read-to-isoform 映射一致 |
| C：clusterj 3′ 中间代表 | 参考 `T(0,1000,100)`；5 条 `T(100,800,0)`；再加入一条 `T(100,830,0)`；`sw_score=-1`，3′ 参数使用默认值 | 添加 singleton 前有 2 个 isoform，添加后仅剩参考 | 添加前后均保留端点 800 的受支持结构；不能把这 5 条原始证据转化为端点 830 的独立支持 |

验收不能只比较 isoform 数量：还要检查外显子坐标、映射、unused 和计数。特别是 A，当前未分批结果中的普通长 read 也不应被直接当作正确答案。

## 3. 问题 A：先阻断 overlap 的新增回归

涉及 [cluster_overlap.rs](../../src/cluster/cluster_overlap.rs) 中的 `should_drop_read`、`filter_pair` 和 `batch_overlap_merge`。

### 根因

新规则只检查来源 read 的 SL 分数及双方 5′ 距离。来源可以并入一个不具备 SL 保护的普通 read，而 `merge_subreads` 仅合并成员，不保留 SL 证据。该普通代表在下一轮会按低分 read 并入参考。

`filter_pair` 还会访问已经标记为 dropped 的 read 容器。在复现 A 中，普通长 read 先并入参考，随后又吸收 SL read；末尾的成员保全逻辑将这个容器恢复，形成下一轮会消失的低分代表。

### 推荐的最小修改

1. 收紧第二 pass 中新增的“不同长度、同 5′ 端”例外：当来源是 SL read 时，read 容器本身也必须满足 overlap 的 SL 分数条件。参考仍走既有身份规则和 5′ 距离校验。
2. 该 SL 例外不能把来源并入已 dropped 的 read 容器。保持成员保全逻辑，但不能依赖它恢复一个已经丢失科学证据的代表。
3. 不通过提高容器 `tx.score` 伪造原始 SL 测量值，也不把所有吸收来的普通 reads 变成 SL 支持。
4. 两条真实 SL reads 的不同长度合并仍需满足原有 exon/intron 距离和 5′ 窗口条件。

这会有意保留原始 SL 代表，而不是强制使用更长的普通 read。混合分数且普通长 read 无法并入其他结构时，可能多保留一个候选 isoform；这是可解释的保守行为，优于丢失 SL 结构。

本步保持初始第一 pass 与等长 read 的既有规则，不宣称解决 overlap 所有历史上的顺序或分批差异。新增例外的跨轮次行为必须通过 A 及其边界变体验证。

## 4. 问题 B：统一同结构代表和证据

涉及 [clusterj.rs](../../src/cluster/clusterj.rs) 中的 `freeze_terminal_cluster_support`、`build_exact_duplicate_representatives`、`target_is_preferred_container` 和 `merge_tracks_by_name`。

### 根因

同结构分组使用最后一个下标作为代表，未考虑 SL 证据；后续保护判断又依赖代表自己的原始分数。选到普通 read 后，其他 reads 的有效 SL 支持不能保护这个代表。

仅将 `group.last()` 改成最高分仍不充分：等长合并的方向判断也使用 `target_idx > source_idx`，且不同批次可能先消费普通 read。因此代表选择、合并方向和分批前的归并需要一致。

### 推荐修改

1. 先在完整 corrected locus 的原始 read 实例上冻结支持度，再处理同结构归并；顺序不能交换。
2. 在分批前，把完全相同结构的 read 实例归并到一个确定代表。沿用现有结构身份规则，参考与 reads 分开，不能跨基因、染色体或链合并。
3. 同结构组优先选择具有有效 SL 保护的原始 read；其后使用明确、稳定的次序，例如原始分数、read 名称及必要的输出元数据。不得用输入位置决定不同记录的优先级。
4. 合并成员时保留每个 `ReadInstance`，并保留选中原始代表的已冻结支持度；不能对各成员已冻结的窗口计数求和，同一窗口已经包含这些 reads。
5. 消除与该策略冲突的“最后下标胜出”路径。优先复用现有分组和归并逻辑；若仍保留 candidate pruning，其代表规则必须与实际归并一致。

完全相同结构的普通 read 可以跟随组内有证据的 SL 代表。这是有意统一同结构组的候选映射；不要求其他不同结构的 reads 在原始 mapping 中全局唯一，也不更改后续计数规则。

必须补充反例：仅 1 条 SL read 加多条同结构普通 reads，不能因归并后成员很多而达到 `min_five_prime_cluster_support=2`。冻结时没有达标的证据，归并后仍不能被“补足”。

## 5. 问题 C：保护原始端点，防止中间代表绕过保护

涉及 [clusterj.rs](../../src/cluster/clusterj.rs) 中的 `TerminalClusterSupport`、`three_prime_protected_from_merge`、`MergeContext::should_merge_into` 和两个成员合并分支。

### 根因

当前保护只比较这一对代表的距离：`800 → 830` 在 50 bp 容差内，因此允许；端点 830 自身只有 1 条支持，随后 `830 → 1000` 又获准。虽然原始计数被冻结，已经被删除的端点 800 不再参与第二次判断。

### 推荐修改

分为两个必要约束：

1. **不能用低支持端点替代高支持端点。** 对具有有效 3′ 保护的来源，若 read 容器在对应端点没有独立、已冻结的有效 3′ 支持，则拒绝这次代表替换。参考仍按原始端点到参考的容差判断。这样 C 中的端点 800 被保留，singleton 830 可以按自己的证据处理。
2. **已经合并的保护证据必须保留原始坐标。** 即使两个 read 代表都受支持，也不能允许多次小距离合并逐渐移出最初的保护范围。后续比较应覆盖此前保留的原始端点，而不只看当前代表的位置。

第二项可用很小的私有状态实现：每个代表分别记录有效 SL 5′ 和有效同剪接链 3′ 证据的坐标上下界 `Option<(min, max)>`。同一染色体和链上，要保证所有原始端点距离目标不超过容差，只需比较最小值和最大值，不必保存全部 reads 的端点列表。

- 在完整 locus 冻结支持度后，仅对已达到对应保护条件的原始 reads 初始化坐标范围。
- 合并只取原始坐标范围的并集；不改变冻结计数、不移动证据坐标、不修改原始分数。
- 新的合并目标必须通过范围两端的距离检查。例：原始端点 800 合并到 840 后，再考虑 880；不能因为两步各为 40 bp 就越过 50 bp 限制。
- SL 使用对应 merge kind 的 5′ 容差；3′ 保护沿用 `SameJunction` 的适用范围。不要把一个剪接链的 3′ 证据冒充另一个剪接链的支持；跨链截短合并按现有规则单独处理和测试。
- 两处实际成员合并、同结构归并及跨 batch 复制都必须保留这份私有状态。
- 如果多种保护条件冲突，拒绝代表替换并保留候选，不用一个综合分数抵消另一类端点证据。

这份坐标状态用于约束合法合并，不是新的支持度估计，也不输出到 BED/TSV。实施时可以扩展现有私有类型，不建立通用证据框架。

4. 加入端点保护不能弱化的判断和原始坐标约束，确保 C、渐进漂移及跨批支持度测试通过。
5. 验证 CLI、flow、计数和基准；仅在行为确定后更新 `CHANGELOG.md` 的 Unreleased 条目及现有 CLI/行为说明。

预计生产代码修改集中在两个聚类实现文件。CLI、flow 配置及缓存代码原则上无需改动：它们已调用共享实现，现有 source fingerprint 会使更改后的代码生成不同缓存身份。仍应沿用既有缓存回归检查，确认旧结果不会被误复用。

## 8. 完成标准与风险

实施后运行已有的格式检查、严格 Clippy、全 feature 单元/集成/doctest、基准编译和两个新基准的 `--test` 模式。当前审阅基线是 353 个库测试通过，新增用例完成后的数量以实际执行结果为准。

涉及性能的验收使用同一机器、同一参数比较修改前后的 release Criterion 数据；fixture 的 `--test` 通过只能说明断言成立，不能证明性能没有退化。新的端点判断应为每个候选 O(1)，同结构预归并应复用现有哈希分组。

主要行为风险是混合分数场景会改变被保留的代表、原始候选映射或 isoform 数。这些变化必须逐项对应本方案的证据规则；不能通过直接刷新 goldens 将未解释的差异纳入预期。

完成要求是 A/B/C、边界变体及已有科学真值回归全部通过，并明确记录有限的行为变化。本文不承诺贪心聚类在任意输入下完全满足交换律或分批等价；超出这些端点问题的新差异需独立分析。

## 9. 执行与复审记录（2026-09-06）

- A：在共享 `should_drop_read` 路径限制第二 pass 的新增 SL 例外；read 容器必须仍存活且原始分数达到阈值。第一 pass、等长规则、参考身份及禁用 SL 的行为不变。
- B：冻结支持度后、分批前归并完全同结构 reads；使用原始 SL 保护和稳定元数据选择代表，保留所有 read 实例。未增加有效 SL 支持的普通成员不会被计作 SL 观测。
- C：拒绝受支持 3′ 端点被无独立支持的 read 代表替换；通过私有坐标上下界保留原始有效端点，覆盖两处实际合并、同结构归并和跨 batch 复制。SL 的冻结计数仅用于初始化有效坐标范围，不保留未使用的计数字段；3′ 保留原始计数以检查 read 容器的独立支持。
- 未新增依赖、公开 API、CLI 配置或输出字段；更新仅进入现有 Unreleased、CLI 和行为说明，未改写 v0.3.1、创建 tag 或发布。

回归测试先在修改前确认 A/B/C 和 3′ 渐进漂移失败，再验证修复。补充 SL 渐进漂移、普通中间代表、同名不同元数据、参考/基因身份隔离、单条 SL 不升级以及截短链不捐赠 3′ 支持的反例。

独立复审未发现本次实现新增的可操作正确性缺陷。复审指出，旧 500-read 单元 fixture 的重复结构在预归并后不足以触发真实分批；新增 CLI fixture 使用每个 locus 超过 500 个不同结构，覆盖 499/500/501、正负链及真正的单/多 worker，已通过。两种 flow 模式另验证了计数总量和输入 read 实例守恒。

flow 的 unique assignment 会重新评估普通 read 与候选结构的距离，因此最终普通 read 的目标不一定等于原始聚类 mapping。测试要求保留受支持结构及其最低证据数量，并检查最终总量守恒，不错误地锁定普通 read 的旧目标。未刷新任何 golden 文件来掩盖行为差异。

性能复审发现，先归并重复结构会把大量成员装入少量代表，使端点变异数据在中间代表间反复复制大集合。首版 20k terminal 基准由约 195 ms 退化到约 953 ms。采样确认热点在集合复制、字符串分配和哈希，而非端点保护。

最终修复保留原有配对顺序和即时端点证据传递，只记录每次实际合并的来源边；保留节点在结束时才迭代汇总来源成员。read 一旦成为来源即 dropped，不能再接收新边；参考永不成为来源，因此来源图无环，延后成员展开与原来的即时集合并集等价。采用独立根节点的访问标记处理菱形路径，保留多目标映射；访问数组复用，不对每个孤立节点重新分配。naive 对照继续即时展开，比较保留节点的成员和保护范围；新增正负链、单/多外显子、双根和重复标签实例的精确测试。

未保留试验中的自定义 read 哈希或重复克隆分支，继续使用标准库集合。来源图使用每批 O(N + E) 内存，稠密且不分批时 E 仍可能为 O(N²)；这不是任意大 locus 的线性复杂度承诺。

性能比较：使用保存的修改前、精确最终 release 基准二进制，同机单线程运行，10 samples、1 秒 warm-up、1 秒 measurement；目标 fixture 和参数保持一致。短采样结果用于识别较大退化，不外推到真实实验数据。
